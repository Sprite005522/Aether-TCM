# Aether-TCM (以太-中药分子动力学推演平台)

本项目构建了一个高性能异构计算平台，通过 **Java 业务调度层**、**MySQL 数据持久层**与 **Python 化学信息学计算引擎**的深度解耦，实现了对海量中草药成分分子的理化指标（LogP、分子量）扫描及结合能动力学推演。

---

## 🏛️ 系统架构演进逻辑

### 一、 异构计算骨架与跨语言协议 (Infrastructure)
为了平衡业务开发的严谨性与科学计算的灵活性，系统采用了 Java (JDK 17) 与 Python (3.10) 的异构分层架构。
* **底层通讯机制**：弃用传统的 RESTful 接口，采用基于 **HTTP/2** 的 **gRPC** 协议。通过 **Protocol Buffers 3** 定义二进制契约，显著降低了分子结构数据在跨语言传输过程中的序列化开销。
* **工程化挑战**：在 Windows 环境下攻克了 **WSA Error 10048** 端口冲突，并针对 Python 3.12 版本的 `grpcio` 构建冲突，确立了基于 `venv` 的虚拟环境隔离规范。

### 二、 核心模拟算法与化学引擎 (Calculation Engine)
计算核心由 Python 端的 **RDKit** 科学库驱动，实现了从非结构化文本到结构化化学特征的提取。
* **算法逻辑**：系统接收 **SMILES (简化分子线性输入规范)** 编码，利用物理引擎解析其三维拓扑结构，并基于 **Lipinski 五倍律** 计算脂溶性参数 (LogP)。
* **异常鲁棒性**：针对中药成分数据源中存在的格式污染（如将分子式错误标识为 SMILES），引擎内置了异常捕获与校验机制，确保非法数据不干扰整体批处理流程。

### 三、 数据库持久化与高性能连接池 (Persistence)
为支撑大规模药库扫描，系统从单体模拟进化为由 **MySQL** 驱动的自动化流水线。
* **连接策略**：引入 **Alibaba Druid** 连接池，利用池化技术复用 TCP 连接，解决了高频推演下数据库握手导致的 I/O 瓶颈。
* **持久化建模**：设计 `tcm_molecules` 物理模型，采用 **DAO (Data Access Object) 模式** 实现了数据库结果集（ResultSet）到业务对象（POJO）的解耦映射。

## 🛠️ 工程痛点解决纪录 (Engineering Problem Solving)

在开发过程中，针对多个关键技术冲突进行了深度调优：

1. **Protobuf 字节码对齐**：
   在集成联调中，Java 端报 `isStringEmpty` 方法缺失错误。经溯源确定为 gRPC 生成的 Java 桩代码与本地 Maven 依赖版本不一致。通过强制对齐 **protobuf-java 3.24.0** 依赖，解决了运行时符号解析失败的问题。

2. **数据库安全协议适配**：
   MySQL 8.0 默认认证协议与旧版 Java 驱动存在握手冲突。通过在数据库端重构 `root` 权限为 `mysql_native_password` 认证模式，成功建立了稳定、安全的持久化链路。

3. **编译器索引同步与类路径治理**：
   针对误操作导致的包名冲突及“双胞胎类”现象，通过物理清理 `target` 编译目录并执行 **Maven Lifecycle Clean/Compile**，实现了代码逻辑在物理路径与字节码层面的绝对对齐。

## 📈 现阶段推演效能
目前平台已具备对 **12 组** 典型中药核心成分（包含青蒿素、甘草酸、补骨脂素等）进行一键全自动化推演的能力，能够精准捕捉分子能级的细微差异，为后续大规模中药方剂的药理研究提供了坚实的数字化底座。
